# specify-feature

Write a feature spec under `docs/specs/` using `docs/templates/feature-spec.md`.

1. Read `docs/PRODUCT.md`, `docs/SECURITY.md`, `GLOSSARY.md`, and `docs/specs/ui-factory-convention.md`.
2. Draft testable **behavior** acceptance criteria and proposed seams (see `docs/TRADUZ-TDD.md`).
3. If the feature has a **user-visible screen** or changes `frontend/src/**`, fill **UI & layout** and **Accessibility (a11y)** sections in the spec. Do not leave them empty or “TBD” without human approval.
4. Save to `docs/specs/<feature>.md`.
5. Stop unless the user asked to implement.
